# Facilitator guide

## Before the session

1. Ask the participant to use a private or fresh browser profile when practical.
2. Open `https://qualcanvas.com/pilot` and read the safety note together.
3. Confirm that all material will be fictional, synthetic, or already public.
4. Do not ask the participant to reveal credentials, private emails, customer data, or research-participant data.
5. If recording the call or screen, obtain separate explicit consent. The QualCanvas pilot form does not grant recording
   consent.

## Opening script

> We are testing QualCanvas, not you. Please say what you expect to happen and what you are looking for. I will usually
> stay quiet. If you become completely blocked, ask for help; needing help is useful evidence.

## During the tasks

- Start a timer when the participant begins each task.
- Record the first place they hesitate for more than ten seconds.
- Record wrong turns and recovery, not only final success.
- Do not teach the interface until the participant is blocked.
- If help is necessary, give the smallest neutral prompt possible and record it.
- Stop immediately if real or confidential data appears; remove it from the workspace before continuing.

## Neutral prompts

- “What are you looking for?”
- “What did you expect that control to do?”
- “What would you try next?”
- “What tells you the task is complete?”

Avoid prompts that name a button, menu, or desired route.

## Closing script

Ask the participant to complete the feedback form on `/pilot`. Then ask:

1. Which part felt least predictable?
2. What would you need to trust this with real research?
3. What would make you return tomorrow?

Record only product-relevant observations. Do not record sensitive details about the participant or their research.

## Triage after 5–10 sessions

Group observations by task and underlying cause. Prioritise repeated failures, data-loss/security risks, accessibility
barriers, and first-use dead ends. Treat one-off visual preferences as low confidence unless they block a task.
